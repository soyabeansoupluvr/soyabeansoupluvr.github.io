The problem

01 — CONTEXT

The Kokomo Umpires Association recruited and trained baseball umpires through a private Facebook group — which meant the people the organizer most wanted to reach, prospective umpires outside the group, had no way in. There was no public schedule, no home for training materials, and no path for an interested candidate to raise a hand short of tracking someone down personally.

Working from a client interview with the association's organizer, our team scoped a public-facing website with a clear mandate: make it easy for outsiders to discover the association, see the schedule, and express interest — and make it easy for one non-technical organizer to run the whole thing. The client asked for it to be live by early spring, in time for the baseball season.

System design

02 — DESIGN

The site is a database-driven PHP application on MariaDB, designed the long way: problem definition, prototyping, data flow diagrams, a full data dictionary, then conceptual, logical, and physical design before a line of production code — all captured in a 121-page project report. Every table was normalized to third normal form, with InnoDB for ACID transactions and PDO for secure database access.

  • PUBLIC Five public pages. Home/About with a highlight carousel, photo gallery, event schedule, training document library, and contacts.
  • JOIN US Interest form. Candidates submit name, email, phone, and comments — routed straight to the organizer's email instead of a database, by design.
  • ADMIN In-page CMS. Signed-in administrators manage events, documents, gallery photos, contacts, and the About copy (via a Quill editor) directly on each page.
  • DATA Six MariaDB tables in 3NF. Administrators, schedule, documents, images, contacts, and form settings — primary-key indexed for a read-heavy workload.
  • INFRA Shared PHP infrastructure. Reusable header/footer, a PDO connection handler, and session login/logout — twelve modules in all.

Security & privacy choices

03 — CONTROLS

Hashed admin credentials

Administrator passwords are stored only as encrypted hashes, with a forced password-change flag and reset flow for account hygiene.

PDO everywhere

All database access runs through a PDO connection handler with parameterized transactions, hardening the site against SQL injection.

Privacy by omission

Join Us submissions are emailed to the organizer rather than stored, so the site never accumulates a database of candidates' personal information.

Deliberately public

No members-only area, at the client's request — every page works without login, which removed a whole class of account-security risk.

Sized for reality

Physical design matched the workload — hundreds of daily reads, tens of writes — so indexing stays lean and the site stays fast on budget hosting.

Built to hand off

Every admin task — events, documents, photos, contacts — is a form on the page it affects, so a non-technical organizer runs the site without help.

Team & process

04 — DELIVERY

This was a five-person capstone team — the Coding Nomadz — working from a real client interview to a real deployment. We ran the full systems-analysis lifecycle: requirements and constraints from the interview, paper prototypes, data flow diagrams, a complete data dictionary, and conceptual, logical, and physical database design, each reviewed before implementation began.

Implementation and testing closed the loop against the original requirements, and the site shipped on a third-party host ahead of the client's start-of-season deadline.

Outcome

05 — RESULTS

The site gives the association a path out of the private Facebook group: a schedule anyone can check, training materials anyone can download, and a one-form path for new umpires to join. It shipped to kokomoumpires.com ahead of the season deadline and is live today as a pilot deployment while the association evaluates full adoption.
